00 / Orientation

Start here: your safe Batch lab

Foundation

What Batch is (and what it is not)

Core conceptNo install needed

Batch is the scripting language interpreted by cmd.exe, the traditional Windows Command Prompt. A Batch file is plain text with a .bat or .cmd extension. .cmd is the conventional choice for modern Windows; both are usually handled by the same interpreter.

Batch excels at

Launching programs, moving files, calling built-in Windows tools, small menus, log parsing, and glueing command-line utilities together.

Choose another tool when

You need structured data, modern Unicode handling, complex networking, parallel work, reliable JSON/CSV, or long-lived software. PowerShell, Python, or a compiled tool may be clearer.

Batch has no native function keyword, arrays, objects, or exception handling. Its closest equivalent to a function is a subroutine: a label called with call :label arguments. The rest of this manual shows how to work safely within those limits.

Make, run, and inspect a script

  1. Create a folder such as %USERPROFILE%\Desktop\BatchLab.
  2. Use a plain-text editor; save as hello.cmd, not hello.cmd.txt.
  3. Open Command Prompt, use cd /d to enter the folder, then run hello.cmd.
  4. Ask the installed Windows version for help: help, help for, or robocopy /?.
HELLO.CMD
@rem The @ prevents this one command from being echoed.
@echo off
rem From now on, print only what the script deliberately prints.

echo Hello from Batch.
echo Script file: %~f0
echo Working folder: %CD%
pause

%~f0 expands to the fully qualified path of the running script; %CD% is the current working directory. They are frequently different, which matters when a script is launched from a shortcut or another folder.

Encoding note: prefer ANSI or UTF-8 without a BOM for the broadest compatibility. Recent Windows builds handle UTF-8 better, but cmd.exe remains sensitive to console code pages and legacy encodings. Keep filenames, variables, and logs ASCII if compatibility matters.

Know the interpreter switches

Switch / settingWhat it controlsPractical guidance
cmd /dSkips AutoRun registry commands for that new shell.Useful when diagnosing a machine-specific startup customization.
cmd /e:onEnables command extensions.Extensions are normally on; modern scripts should explicitly request them with setlocal EnableExtensions.
cmd /v:onEnables delayed expansion using !name!.Use locally, not blindly across all scripts; literal exclamation marks are a trap.
cmd /c commandRuns a command then exits the child shell.Handy for controlled child execution, but adds another parsing layer.
cmd /k commandRuns a command then keeps the child shell open.Helpful while learning or debugging.

Most lessons start with setlocal EnableExtensions DisableDelayedExpansion. That establishes a known script-local environment and avoids inheriting surprising settings from its caller.

Before you automate anything real

  • Use quotes around every path which may contain spaces.
  • Print a computed target before changing it: echo Target is "%target%".
  • Use if exist, if not exist, and explicit error checks instead of assumptions.
  • Keep a log with >>"file.log" 2>&1.
  • Give destructive behavior an opt-in switch such as --apply; default to preview.
  • Run a command with /? on the Windows versions you support.

01 / Basic Batch

Build reliable fundamentals

Basic does not mean shallow. These mechanics are the grammar behind every Batch script, including expert-level ones.

Basic

Lines, comments, and command separators

SyntaxMeaningExample / caution
@commandDo not echo this command before executing it.@echo off is the standard quiet-script opening.
echo textWrite text to standard output.echo( reliably prints a blank line, even if a file named echo exists.
rem textA real comment command.Use it inside blocks and redirections safely.
:: textA label-like comment idiom.Convenient at top level; avoid it in parenthesized blocks or redirected code because it can parse unexpectedly.
one & twoRun two regardless of one's result.Escape a literal ampersand as ^&.
one && twoRun two only when one returns exit code 0.Good for short success chains; use explicit checks in serious scripts.
one || twoRun two only when one fails.A concise fallback or error message.
one | twoPipe standard output from one to two.Each side is normally evaluated in a child command process; see Expert.
^Escape the next special character or continue a physical line.The caret must be the final non-space character for line continuation.
SYNTAX.CMD
@echo off
rem A safe, readable line continuation: caret is last on its line.
echo This sentence is ^
continued on the next physical line.

rem Print characters that normally have command meaning.
echo A ^& B  ^|  C ^> D ^< E  ^(group^)

rem This executes the second echo only if the first succeeds.
echo first && echo success
Quotation is not escaping. Quotes group a path for many commands, but cmd.exe still recognizes several metacharacters during parsing. When a value can contain &, |, parentheses, percent signs, or exclamation marks, learn the Expert parsing rules before embedding it in a command line.

Variables: text, input, arithmetic, and built-ins

Batch variables live in the process environment. Assign with set "name=value": the outer quotes are not stored, preventing accidental trailing spaces. Read a variable with %name%.

VARIABLES.CMD
@echo off
setlocal EnableExtensions

rem Safe assignment form: quote the whole assignment, not the value alone.
set "name=Ada Lovelace"
echo Hello, %name%.

rem Ask for input. An empty reply leaves the prior value unchanged.
set /p "city=City (Enter keeps current): "

rem /a evaluates integer arithmetic; no percent signs are required inside it.
set /a total=7 * (3 + 2)
echo total=%total%

rem Substring and string replacement are text operations.
set "file=report-final.txt"
echo First six letters: %file:~0,6%
echo Replace dash: %file:-=_%
endlocal
FormUseImportant detail
set "x=value"Assign text.set "x=" deletes it. set x lists matching variables.
%x%Percent expansion.Expanded when a parenthesized block is parsed, not necessarily when each line runs.
%x:~start,length%Extract text.Negative offsets count from the end: %x:~-4%.
%x:old=new%Replace text.%x:*prefix=% removes through the first matching prefix.
set /aInteger arithmetic and bitwise work.Operators include + - * / %% << >> & ^ |; division is integer division. Escape operators when needed outside the expression.
set /pRead one line from the user or redirected input.Validate input; it is untrusted text, not a number merely because you asked for one.
setxPersist a user/system variable for future processes.It does not update the current shell; avoid using it casually in scripts.
Useful dynamic values

%CD% current directory; %DATE% and %TIME% are locale-dependent display strings; %RANDOM% is a pseudo-random integer from 0 to 32767; %ERRORLEVEL% exposes the previous program's exit code when no same-named environment variable shadows it; %CMDEXTVERSION% reports the extension version. Do not use %DATE% as a portable filename timestamp: its layout changes with regional settings.

Arguments and path modifiers

A script receives positional arguments in %0 through %9. %0 is the script invocation; %* is the original complete argument list. Use shift to bring argument 10 onward into range.

FormReturns for argument 1
%1The argument exactly as supplied, perhaps including quotes.
%~1The argument with surrounding quotes removed.
%~f1Fully qualified path.
%~d1 / %~p1Drive / path portion.
%~n1 / %~x1Base filename / extension.
%~dp1 / %~nx1Drive+path / base name+extension.
%~dp0The folder of the script itself, with a trailing backslash. Fundamental for self-contained tools.
%~z1 / %~t1File size / modified date-time (if the argument names an existing file).
ARGUMENTS.CMD
@echo off
setlocal EnableExtensions

if "%~1"=="" (
  echo Usage: %~nx0 "a file or folder"
  exit /b 64
)

echo Script folder: %~dp0
echo Target full path: %~f1
echo Name only: %~nx1
endlocal

Quote at the use site: if exist "%~f1", type "%~f1", copy /y "%source%" "%destination%". Never construct a command by adding quotes to an already quoted value unless you have deliberately normalized it first.

Conditions, labels, and control flow

PatternMeaningGotcha
if "a"=="b" commandString comparison; /i ignores case.Quote both operands so empty values still produce valid syntax.
if exist "path" commandTest whether a file or directory exists.It does not prove a path is safe to modify.
if defined name commandTest whether a variable is defined.Requires command extensions.
if errorlevel N commandTrue when exit code is N or greater.Check from largest to smallest, or use if not errorlevel 1 for success.
goto :labelJump to a label.Overuse creates spaghetti flow; prefer subroutines and structured blocks.
call :label argsEnter a subroutine.Return with exit /b code, not plain exit.
choice /c YNRead a controlled single-key answer.Better than set /p when input must be one of a few choices.
CHOICE.CMD
@echo off
setlocal EnableExtensions
choice /c YN /n /m "Continue with the safe preview"

rem CHOICE returns 1 for Y and 2 for N. Check high values first.
if errorlevel 2 (
  echo Cancelled. Nothing changed.
  exit /b 0
)
echo Preview would run here.
endlocal
Exit code convention: zero usually means success; nonzero means some failure. The exact values belong to each command. A good script documents the values it returns and propagates a failing tool's code deliberately.

FOR loops: the four essential forms

In a Batch file, a FOR variable uses two percent signs: %%F. At an interactive prompt it uses one: %F. FOR variable names are case-sensitive and should not be digits.

LOOPS.CMD
@echo off
rem 1) A simple set of words or matching files in the current folder.
for %%F in (*.txt) do echo Found: "%%F"

rem 2) /D visits matching directories, not ordinary files.
for /d %%D in (*) do echo Folder: "%%D"

rem 3) /R recurses from a root; use it for inventory before changes.
for /r "%~dp0" %%F in (*.log) do echo Log: "%%~fF"

rem 4) /L is a numeric sequence: start, step, end.
for /l %%N in (1,1,5) do echo Number %%N

%%~fF, %%~nxF, and related modifiers work for a FOR variable just like %~f1 works for an argument. The Advanced section covers for /f, Batch's very powerful line/token parser.

Files, folders, and current directory

Navigate

cd/chdir shows or changes the directory. Use cd /d "D:\work" to change drive and folder together. pushd saves the current folder; popd restores it.

Inspect

dir /a /o:n lists all items sorted by name. type "file.txt" writes a text file. tree /f shows a hierarchy. attrib views attributes.

Change carefully

md/mkdir creates folders; copy, move, and ren alter files. del/erase and rd/rmdir remove items and need deliberate safeguards.

SAFE-FILE-LAB.CMD
@echo off
setlocal EnableExtensions
set "lab=%~dp0lab"

rem Build and inspect a folder owned by this demonstration.
if not exist "%lab%\" mkdir "%lab%"
echo example > "%lab%\note.txt"
copy /y "%lab%\note.txt" "%lab%\note-copy.txt" >nul
dir /b "%lab%"

rem Preview a cleanup. Replace ECHO only after independently verifying %lab%.
echo del /q "%lab%\note-copy.txt"
endlocal
Do not normalize destruction. del /s, rd /s /q, and broad wildcards can erase data without the Recycle Bin. This course shows them only as commands to recognize; design a preview, an exact owned root, and an explicit --apply gate before you ever use them.

Redirection: send data where you intend

FormEffect
command > "out.txt"Overwrite standard output (stream 1).
command >> "out.txt"Append standard output.
command 2> "errors.txt"Overwrite standard error (stream 2).
command > "all.log" 2>&1First send stream 1 to the file, then make stream 2 follow its current destination. Order matters.
command 2>&1 > "out.txt"Different: error goes to the original destination, usually the screen; output goes to the file.
command >nul 2>&1Discard normal output and error. Use only when failures are checked another way.
command < "input.txt"Provide standard input from a file.

A pipe (|) connects one command's output to another command's input. It is excellent for filtering, but it introduces a child-process boundary: do not expect a variable changed inside a piped block to persist in the parent script.

02 / Advanced Batch

Control the parser, data, and outcomes

These patterns are what make a script maintainable after its first successful run.

Advanced

Percent expansion versus delayed expansion

Batch parses an entire parenthesized block before it starts executing the block. Therefore %variable% inside a block normally reflects the value that existed when the block was parsed. Delayed expansion, written !variable!, resolves later—at execution time.

EXPANSION.CMD
@echo off
setlocal EnableExtensions DisableDelayedExpansion
set "count=0"

( 
  set /a count+=1
  echo Percent value looks stale here: %count%
)

setlocal EnableDelayedExpansion
for /l %%N in (1,1,3) do (
  set /a count+=1
  echo Live value: !count!
)
endlocal
endlocal

Use %name%

For values stable across the whole command/block; arguments; values containing literal exclamation marks; simple scripts with no changing state in a block.

Use !name!

For counters and values that change within a block. But delayed expansion can remove or transform literal ! in data, especially while reading files.

The safe file-reading toggle for literal exclamation marks

Read each line while delayed expansion is off, then enable it only where required. The precise handoff is an Expert topic because it combines parsing phases, but the governing rule is simple: never globally enable delayed expansion before consuming untrusted text that may contain !.

FOR /F: parse files, strings, and command output

for /f reads text line by line, skips blank lines by default, and splits each line into tokens using spaces and tabs by default. It can process a file, a literal string, or the output of a command. It is Batch's workhorse text parser—not a full CSV parser.

Source syntaxWhat it means
in (file.txt)Read a file name (unquoted simple name).
in ("literal text")Parse one literal string.
in ('command')Run a command and parse its standard output.
usebackq ... in ("long file.txt")With usebackq, double quotes name a file, single quotes make a literal string, and back quotes run a command.
FOR-F.CMD
@echo off
setlocal EnableExtensions DisableDelayedExpansion

rem Parse comma-separated key,value lines. tokens=1,2* gives %%A, %%B, %%C.
for /f "usebackq tokens=1,2* delims=," %%A in ("%~dp0settings.txt") do (
  echo Key=[%%A] Value=[%%B] Remainder=[%%C]
)

rem Capture a single command-output line: first token from VER output.
for /f "tokens=*" %%A in ('ver') do echo %%A

rem tokens=* removes leading delimiters and keeps the remaining line.
endlocal
OptionPurpose
tokens=1,3,5Choose positions. Each chosen token gets a sequential FOR variable.
tokens=2,*Token 2 and an extra variable containing the rest of the line after it.
delims=,=:Every listed character is a separator, not a multi-character delimiter.
skip=2Skip leading lines in each input file.
eol=;Lines beginning with the chosen single character are ignored.
CSV caveat: quoted commas, escaped quotes, embedded newlines, and arbitrary Unicode make CSV a poor fit for for /f. Call a CSV-aware tool instead of growing a fragile parser.

Errors, logs, and controlled child commands

After an external program or built-in command, examine its exit code immediately. A later command can overwrite it. Capture diagnostic output in a log and give callers a meaningful exit code.

LOGGED-COMMAND.CMD
@echo off
setlocal EnableExtensions DisableDelayedExpansion
set "log=%~dp0run.log"

echo [%date% %time%] Checking a harmless folder... >> "%log%"
dir /a "%~dp0" >> "%log%" 2>&1
set "rc=%errorlevel%"

if not "%rc%"=="0" (
  echo Folder check failed; see "%log%".
  endlocal & exit /b %rc%
)

echo OK. Details appended to "%log%".
endlocal & exit /b 0

The final endlocal & exit /b %rc% is intentional: percent expansion occurs while the local environment still exists, so the numeric code is carried out of scope. The Expert section generalizes that pattern for return values.

call

Calls another Batch file or a subroutine and returns. Without call, invoking another Batch file transfers control and your caller does not resume.

start

Launches a separate process/window. If the first quoted token is present, it is a window title: use start "" "C:\Path\App.exe".

cmd /c

Runs a string in a child interpreter. It is sometimes required by tools, but adds parsing; do not use it as a casual string-evaluation feature.

Text and file tools worth orchestrating

ToolUse in BatchNotes
find / findstrSearch text; findstr supports practical regex-like patterns and recursive search.Check exit codes: no match is often exit code 1, not necessarily a script failure.
sortSort piped or redirected text.Works well in a pipeline: type file | sort.

SEARCH.CMD
@echo off
rem Search .log files below the script folder, case-insensitively, with line numbers.
findstr /s /n /i /c:"error" "%~dp0*.log"
if errorlevel 2 echo FINDSTR itself failed.
if errorlevel 1 echo No matching lines were found.

Batch often coordinates Windows executables. The tools below are not language features; availability, output text, and privileges vary by Windows edition and policy. Treat output as user-facing/localized unless a tool supplies a machine-readable option.

Advanced project: a preview-first inventory tool

This compact example demonstrates argument validation, self-relative paths, logging, for /r, and a separate apply gate. It only lists files; it deliberately does not delete or copy anything.

INVENTORY.CMD
@echo off
setlocal EnableExtensions DisableDelayedExpansion

set "root=%~1"
if "%root%"=="" set "root=%~dp0"
if not exist "%root%\" (
  echo Folder not found: "%root%"
  exit /b 64
)

set "log=%~dp0inventory.log"
echo === Inventory of "%root%" === > "%log%"
for /r "%root%" %%F in (*) do echo %%~zF bytes  %%~fF >> "%log%"

echo Wrote "%log%".
endlocal

03 / Expert Batch

Think like the command parser

Expert Batch is less about clever one-liners and more about predicting each expansion, escaping exactly once, and putting guardrails around irreversible work.

Expert

The parser model: why Batch surprises people

One physical-looking line can be parsed more than once. The exact phases are nuanced, but this mental model prevents most failures:

  1. Read compound syntax. Parenthesized blocks and some operators are recognized as a unit before their individual commands run.
  2. Percent-expand. %variables%, arguments, and many modifiers are substituted early.
  3. Handle command syntax. Redirection, &, |, parentheses, and caret escaping affect how commands are separated or connected.
  4. Delayed-expand, if enabled. !variables! resolve later for the running command.
  5. Possibly parse again. call, cmd /c, and pipe sides can introduce additional expansion/process boundaries.
PARSE-DEMO.CMD
@echo off
setlocal EnableExtensions EnableDelayedExpansion
set "word=before"

(
  set "word=after"
  echo percent: %word%     rem expanded when block was parsed
  echo delayed: !word!     rem expanded when this command runs
)

endlocal
Why pipes deserve special suspicion

Each side of a pipe is generally executed in a separate cmd.exe context. A set value=... inside a piped parenthesized group will not reliably update the caller's variable. Write data to a file, refactor to avoid the pipe, or intentionally invoke a helper if state must return.

Escaping and quoting reference

Do not evaluate user text. Never take text from set /p, a file, a filename, or an environment variable and feed it to call or cmd /c as a constructed command. That turns data into code and invites command injection. Use fixed command templates and quote known path arguments instead.

Subroutines: Batch's function substitute

Place callable labels after a main-script exit /b so execution does not fall into them. Each subroutine gets its own arguments. Use setlocal to avoid leaking working variables; return a value with a controlled endlocal & set handoff.

SUBROUTINES.CMD
@echo off
setlocal EnableExtensions DisableDelayedExpansion

call :ToUpperStub "sample" result
echo Result is "%result%"
endlocal & exit /b 0

:ToUpperStub
rem %~1 = input; %~2 = name of caller variable receiving result.
setlocal
set "localValue=%~1"
rem Batch lacks a general built-in uppercase function; this demonstrates return mechanics.
endlocal & set "%~2=%localValue%" & exit /b 0

That return line works because %localValue% and %~2 expand before endlocal executes. Keep the returned value simple and controlled. If it can contain parser-significant characters, a direct environment return is not enough without careful design.

Good subroutine contract

Document parameters, accepted shapes, output variables, side effects, and exit codes. Prefix local variables (for example _copy_src) to reduce collisions in large scripts.

Good program layout

Header/configuration, argument parsing, main orchestration, exit /b, then named helpers. Avoid jumping into the middle of a helper with goto.

Defensive Batch design

Validate at boundaries

Check required arguments, exact allowed choices, path existence, and permissions before doing work. Use choice for finite menus. Do not use set /a userInput as validation: it evaluates an expression.

Separate preview from apply

Make preview the default. Require an explicit flag such as --apply for changes and log exactly what will change. Make a repeated run safe (idempotent) where possible.

Own your temp paths

Use a unique, script-controlled temp folder and remove only that exact folder after resolving/printing it. Avoid wildcards in cleanup logic.

Preserve failure evidence

Log command, timestamp, current folder, exit code, and stderr. Do not suppress stderr until you have an explicit alternative diagnostic.

APPLY-GATE.CMD
@echo off
setlocal EnableExtensions DisableDelayedExpansion
set "mode=preview"
if /i "%~1"=="--apply" set "mode=apply"

echo Mode: %mode%
echo Would copy "%~dp0source.txt" to "%~dp0out\source.txt"

if not "%mode%"=="apply" (
  echo Preview only. Pass --apply after reviewing the paths.
  exit /b 0
)

rem The real, fixed operation would go here after checks succeed.
echo Apply path intentionally omitted from this teaching sample.
endlocal

Compatibility and performance boundaries

ConcernPractical response
UNC paths (\\server\share)cd does not make a UNC path a current directory in the same way as a drive path. Use pushd "\\server\share\folder"; it can map a temporary drive, then use popd.
Command extensionsStart with setlocal EnableExtensions. If legacy compatibility truly matters, test with extensions disabled and document required behavior.
Long commands / pathscmd.exe has practical command-line and legacy path limitations. Process items in a loop rather than constructing a giant single command.
Language / regional settingsDo not parse display text. Avoid %DATE%/%TIME% for logic. Test on at least one non-English locale if distributing broadly.
Deprecated toolsWMIC is deprecated/optional on current Windows. Prefer currently supported tools or a documented API; test availability before calling it.
SpeedLaunching cmd, findstr, or other programs inside an inner loop is expensive. Use a single tool invocation, built-in expansion, or move high-volume work to a better-suited runtime.

Debugging and test discipline

  • Temporarily replace @echo off with @echo on, or trace a focused block with echo [trace] variable=[%variable%].
  • Use set to list your environment and catch accidental variables or spaces.
  • Run a suspect command alone with command /?; then capture its exit code immediately.
  • Test missing files, spaces in paths, empty input, non-ASCII filenames, access denied, and an already-completed run—not just the happy path.
  • Use cmd /d /v:on /k yourscript.cmd to isolate startup effects and keep the learning shell open.

rem A tiny assertion helper. Call it with a known condition outcome.
call :AssertExists "%~dp0Learn Batch.html" || exit /b 1
exit /b 0

:AssertExists
if exist "%~1" exit /b 0
echo ASSERTION FAILED: expected "%~1"
exit /b 1

Field recipes

Small patterns you can reuse

Read the comments and adapt the fixed, known pieces—not by evaluating arbitrary strings.

Recipes

Locate assets next to the script

SELF-RELATIVE.CMD
@echo off
setlocal EnableExtensions
set "scriptDir=%~dp0"
set "config=%scriptDir%config\settings.ini"
if not exist "%config%" (
  echo Missing configuration: "%config%"
  exit /b 2
)
type "%config%"
endlocal

A controlled menu and retry loop

MENU.CMD
@echo off
setlocal EnableExtensions

:menu
cls
echo 1. Show current folder
echo 2. Show script folder
echo Q. Quit
choice /c 12Q /n /m "Select"
if errorlevel 3 exit /b 0
if errorlevel 2 echo %~dp0 & pause & goto :menu
if errorlevel 1 cd & pause & goto :menu

Make a script-owned temporary workspace

TEMP-WORKSPACE.CMD
@echo off
setlocal EnableExtensions DisableDelayedExpansion
set "work=%TEMP%\LearnBatch-%RANDOM%-%RANDOM%"

Diagnostics

When a Batch script behaves strangely

Fixes
SymptomLikely causeFirst fix to try
"X is not recognized..."Not on PATH, typo, wrong current folder, or extension association issue.Run where X, then use a quoted absolute path or fix the dependency check.
Path with spaces breaksPath was not quoted at the command use site.Use "%~f1", "%variable%", or a fixed quoted path—avoid manual quote concatenation.
Variable prints its old value in a loop/block%var% was expanded while the block was parsed.Enable delayed expansion narrowly and use !var!.
Text loses exclamation marksDelayed expansion was active while reading data.Disable delayed expansion during ingestion; redesign the handoff if necessary.
"Access is denied"ACL/UAC, locked file, protected folder, or a different account context.Do not simply elevate. Confirm target and identity with whoami; log the exact tool error.
if errorlevel 1 runs on success pathChecks are >=, and/or another command overwrote the code.Capture immediately; test codes from highest to lowest; define the tool's success range.
Script exits after invoking another .cmdThe child Batch file was launched without call.Use call other.cmd args when you need to return.
Works at prompt, fails in .cmdFOR and percent syntax differ; file parser has more expansion phases.Use %%F in a file; escape literal percent signs as %%.
Code works in one country/PC onlyParsed localized output, code-page assumptions, installed-tool differences.Use documented machine-readable inputs/switches and test a fresh, non-English environment.

Sources

Windows changes, optional components vary, and every command has its own semantics. Keep this offline guide as your map, then verify the installed system:

  • help — lists commands recognized by your local Command Prompt.
  • help for and help if — internal command details.
  • robocopy /?, schtasks /?, and similar — tool-specific syntax from the installed version.
  • Microsoft Learn: Windows commands reference — current official web reference.
  • Documentation.html — how this two-page offline package is organized and maintained.

This manual intentionally teaches the durable language and workflow rather than pretending every version-specific Windows executable has one timeless syntax. When correctness matters, treat /? and the official command reference as authoritative.
